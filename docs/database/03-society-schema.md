# 03 — Society Database Schema

## Overview

Sprint S03 adds the `societies` table to Supabase PostgreSQL, creating the foundation for tenant entities and society-level boundaries in CHS.

```text
┌───────────────────────┐
│      users (S01)      │
├───────────────────────┤
│ id (PK, UUID)         │
│ phone (UNIQUE, TEXT)  │
│ status (TEXT)         │
└───────────┬───────────┘
            │ 1
            │
            ├─────────────────────────────────────────┐
            │ 1..N (created_by, updated_by)           │ 1..N (actor_id)
            │                                         │
┌───────────▼───────────┐                 ┌───────────▼───────────┐
```

## 1. `societies` Table Specification

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY DEFAULT gen_random_uuid()` | Permanent internal immutable UUID |
| `society_code` | `TEXT` | `NOT NULL UNIQUE` | Human-readable canonical uppercase code `SOC-{CITY_CODE}-{RANDOM_SUFFIX}` (e.g. `SOC-MUM-7K4P2X`, `SOC-PUN-9D3R8A`) |
| `name` | `TEXT` | `NOT NULL` | Official registered name of the housing society |
| `registration_number` | `TEXT` | `NULL` | State registrar co-operative society registration number |
| `address_line1` | `TEXT` | `NOT NULL` | Primary street address, plot, survey number |
| `address_line2` | `TEXT` | `NULL` | Secondary address line, landmark, building complex |
| `locality` | `TEXT` | `NOT NULL` | Neighborhood, area, or sub-locality |
| `city` | `TEXT` | `NOT NULL` | Municipal city or district |
| `state` | `TEXT` | `NOT NULL` | State or union territory (e.g. `Maharashtra`) |
| `pincode` | `VARCHAR(6)` | `NOT NULL` | Indian 6-digit postal PIN code |
| `contact_email` | `TEXT` | `NULL` | Administrative contact email for the society |
| `contact_phone` | `TEXT` | `NULL` | Administrative contact phone number (normalized E.164) |
| `status` | `TEXT` | `NOT NULL DEFAULT 'PENDING'` | Lifecycle state: `PENDING`, `ACTIVE`, `SUSPENDED` |
| `created_by` | `UUID` | `NOT NULL REFERENCES users(id) ON DELETE RESTRICT` | Super Admin who created this society |
| `updated_by` | `UUID` | `NULL REFERENCES users(id) ON DELETE SET NULL` | Super Admin who last updated this record |
| `created_at` | `TIMESTAMPTZ`| `NOT NULL DEFAULT NOW()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ`| `NOT NULL DEFAULT NOW()` | Record modification timestamp |

## 3. Table Constraints & Validation Rules

### Check Constraints
```sql
-- 1. Allowed lifecycle states
ALTER TABLE societies
    ADD CONSTRAINT societies_status_check
    CHECK (status IN ('PENDING', 'ACTIVE', 'SUSPENDED'));

-- 2. Valid society code syntax: SOC-{CITY}-{SUFFIX}
ALTER TABLE societies
    ADD CONSTRAINT societies_code_format_check
    CHECK (society_code ~ '^SOC-[A-Z0-9]{3,4}-[A-Z0-9]{6}$');

-- 3. Valid Indian PIN code syntax: 6 digits, first digit 1-9
ALTER TABLE societies
    ADD CONSTRAINT societies_pincode_format_check
    CHECK (pincode ~ '^[1-9][0-9]{5}$');

-- 4. Minimum length checks
ALTER TABLE societies
    ADD CONSTRAINT societies_name_length_check
    CHECK (length(trim(name)) >= 3 AND length(name) <= 255);
```

### Immutability Trigger
```sql
-- Enforce code immutability after insertion
CREATE OR REPLACE FUNCTION check_society_code_immutability()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.society_code IS DISTINCT FROM NEW.society_code THEN
        RAISE EXCEPTION 'society_code is immutable and cannot be updated once created'
            USING ERRCODE = 'restrict_violation';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER societies_code_immutability_trg
    BEFORE UPDATE OF society_code ON societies
    FOR EACH ROW
    EXECUTE FUNCTION check_society_code_immutability();
```

### Unique Constraints
```sql
-- Unique society code (enforced case-insensitively)
CREATE UNIQUE INDEX societies_code_unique_idx ON societies(upper(society_code));
```

## 4. Query Optimization Indexes

```sql
-- Filter societies by status with chronological ordering (for roster table)
CREATE INDEX societies_status_created_idx ON societies(status, created_at DESC);

-- Geographic filtering and grouping (city, state)
CREATE INDEX societies_location_idx ON societies(state, city);

-- Fast text search by society name (case-insensitive prefix / full name)
CREATE INDEX societies_name_lower_idx ON societies(lower(name));

-- Suspension reasons active filter index
CREATE INDEX society_suspension_reasons_active_idx ON society_suspension_reasons(is_active, allows_manual);
```

## 5. Referential Integrity & Foreign Key Behavior

- **`created_by`**: `REFERENCES users(id) ON DELETE RESTRICT`. A user record cannot be deleted if they are recorded as the creator of an existing society.
- **`updated_by`**: `REFERENCES users(id) ON DELETE SET NULL`. If an administrative updater user is ever deleted, the reference is cleared without deleting the society.
- **Future Child Tables** (`buildings`, `units`, `society_members`):
  - Must all specify: `society_id UUID NOT NULL REFERENCES societies(id) ON DELETE RESTRICT`.
  - `ON DELETE RESTRICT` is required to prevent accidental cascading deletion of an entire housing society's infrastructure or membership records.

## 6. Audit Trail Alignment

Platform mutations to `societies` leverage `platform_audit_logs`:
- `actor_id`: Authenticated `SUPER_ADMIN` UUID (or system actor for automated actions).
- `action`: `SOCIETY_CREATED`, `SOCIETY_ACTIVATED`, `SOCIETY_SUSPENDED`, `SOCIETY_REACTIVATED`, `SOCIETY_PROFILE_UPDATED`.
- `target_user_id`: `NULL`.
- `details`: JSONB structure:
  - For `SOCIETY_SUSPENDED`:
    ```json
    {
      "society_id": "7b63fcf0-3889-4bc2-84cf-d5e6834ff7f1",
      "society_code": "SOC-MUM-7K4P2X",
      "previous_status": "ACTIVE",
      "new_status": "SUSPENDED",
      "reason_id": 1,
      "reason_code": "PAYMENT_OVERDUE",
      "reason_label_snapshot": "Payment overdue",
      "suspension_origin": "MANUAL",
      "reason_details": "Optional operational context (mandatory for OTHER_REVIEW_REQUIRED)"
    }
    ```
- `client_ip` and `user_agent`: Captured from HTTP request context.
